# 考拉食堂 · 后端说明（round-1）

作者：羊驼后端组长　日期：2026-11-09　分支：`round-1`
接口以 `docs/接口约定.md`（v2.3.1）为准；厨驼操作见 `docs/厨驼使用说明.md`；照片存储选型见 `docs/照片存储方案.md`。

## 1. 技术栈与原则
- Cloudflare Worker（TypeScript + Hono）+ D1（菜品数据）+ **Workers KV（照片，默认）**；D1、R2 作为可切换的备选照片存储。
- **已去掉 Workers AI，改由厨驼写菜谱**：上传菜品后状态是 `pending`，羊驼「厨驼」用 `tools/chef.py` 领任务、看照片、交草稿（`draft`），大王确认后变 `confirmed`。手动录入随时可用。
- 全部只在本地跑（`wrangler dev --local`，Miniflare 模拟 D1/KV/R2，数据在 `worker/.wrangler/state`）。没有建任何线上资源、没有部署、没有花钱。
- 只用免费额度内的功能；需要绑卡的（R2）默认不启用。

## 2. 启动
见根目录 `README.md`「后端」一节（安装依赖 → `./scripts/init-dev-vars` → `npx wrangler d1 migrations apply DB --local` → `npm run dev`（8787）→ `./scripts/seed` → 测试）。
换端口：`PORT=8801 npm run dev`。常驻实例：`nohup npm run dev > /tmp/koala-worker.log 2>&1 &`。

## 4. 数据表（D1）
| 表 | 作用 | 要点 |
|---|---|---|
| `dishes` | 菜品 | id(uuid)、name(≤30)、category(6 个固定)、note(≤200)、ingredients/steps/tips(JSON 文本)、servings、total_time、source(chef/manual)、chef_status(pending/draft/confirmed)、draft(JSON)、requested_note、chef_requested_at、claimed_at、draft_at、created_at、updated_at |
| `dish_photos` | 每道菜 1–9 张照片 | dish_id、r2_key（照片键 `uuid.ext`，历史列名，三种存储通用）、content_type、size、position |
| `photo_blobs` | 仅 `PHOTO_STORE=d1` 时存照片本体 | key、content_type、size、data(BLOB) |
| `orphan_photos` | 删除失败的照片键，稍后重试 | key、store、size、attempts（每次厨房写操作后后台重试 ≤20 条，且不超当天剩余次数） |
| `kv_usage` | KV 当天 put+delete 次数 | day(UTC 日期)、ops |
| `settings` | 开关 | chef_enabled |

## 5. 厨驼流程
1. 大王上传菜（`POST /api/kitchen/dishes`，`mode=chef`）→ `pending`。
2. 厨驼 `python3 tools/chef.py list` 看待写的菜 → `show <id>` 领取（30 分钟内别人领会 409）并下载照片到 `/tmp/koala-chef/<id>/` → `template` 拿模板 → `submit <id> 草稿.json` 交稿 → `draft`。
3. 大王在前端看草稿：确认（`confirm`，可带修改，合并后按严格规则再校验）→ `confirmed`；或丢弃（`discard-draft`，只对 `draft` 有效，否则 409 BAD_STATE）回到 `pending`；也可以随时手动编辑（直接 `confirmed`、取消厨驼任务）。
4. 设置里关掉厨驼（`chef_enabled=false`）时，厨驼的 tasks / claim / draft 全部返回 403 CHEF_DISABLED。
5. 草稿规则（chef 严格模式）：食材 ≥1 且每条 amount 非空；步骤 3–12 步；caption ≤12 字；火候别名会被规范（旺火→大火）；步骤前的编号会被去掉。实在写不出可以 ingredients/steps 都留空 + `chef_message` 说明原因。
6. `CHEF_MOCK=1`（只用于联调）：pending 满 20 秒自动出示例草稿。

## 6. 生成器抽象 · 如何替换生成器
业务只认两样东西：`RecipeDraft`（草稿结构）和 `normalizeDraft()`（统一校验/清洗），不关心草稿从哪来。
- 现在唯一的来源是 `ChefSource`（`src/generator/source.ts`，异步：草稿通过 `/api/chef/tasks/:id/draft` 进来）。
- **要接一个外部草稿来源，只需新增一个实现 `RecipeDraftSource` 的类**：
  ```ts
  export const MySource: RecipeDraftSource = {
    id: "my-source", async: false,
    async generate(input) {
      const raw = await 调用外部服务(input);          // 拿到原始文本或 JSON
      return normalizeDraft(parseDraftText(raw), "chef"); // 统一过校验，不合格会抛 VALIDATION
    },
  };
  ```
  然后在调用处把返回的草稿用 `draftColumns()` 写进 `dishes`（状态置 `draft`）。路由、表结构、前端都不用改。
- 注意：接任何要花钱的生成服务前先报大王审批。

## 7. 照片存储
- `PHOTO_STORE` 选择：`kv`（默认）| `d1` | `r2`（只在 `wrangler dev --env r2` 下有 R2 绑定；默认配置不需要 R2，选 r2 又没绑定会报清楚的错）。
- 上传：嗅探文件头只收 JPEG/PNG/WebP/GIF；单张 ≤1MB（1,048,576 字节，超了 413「照片太大了（1,030KB），上限 1,024KB」，KB=ceil(字节/1024)，批量时前面加「第 N 张」）；每道菜 1–9 张。先写照片、再一次性批量写 D1，失败会回滚已写照片，不留半条菜。
- 读取：`GET /api/photos/<key>`，只返回 `dish_photos` 里登记过的键（删掉的照片立刻 404），带一年 immutable 缓存。
- 上限（1024 进制）：
  - 容量：上限固定 950MB = 996,147,200 字节（本地可用 `STORAGE_LIMIT_BYTES` 调低；三种存储都算，已用量 = dish_photos.size 之和 + orphan_photos.size 之和）。超了 **507 STORAGE_FULL**「照片柜满啦，删掉一些旧照片才能继续上传～」。
  - KV 每天次数：`KV_DAILY_WRITE_LIMIT` 默认 1000，put 和 delete 合并计数（D1 `kv_usage`，UTC 日）。超了 **429 STORAGE_QUOTA**「今天食堂的照片柜塞满啦，明天再来传吧～」。
  - **两个都超先判 507**。都在写之前预检，被拦时一张也不写。
  - KV 真的报限额错误（官方 1,000 次/天、同键 1 次/秒）也会转成 429。
  - 删除永远成功：存储删不掉（没次数或出错）的键记进 `orphan_photos`，之后自动重试。
- 用量：`GET /api/kitchen/storage`（要登录）→ `{store, photo_count, capacity:{used_bytes, limit_bytes, percent, level, photos_left}, daily_ops:{used, limit}}`。`percent` 保留 1 位小数只做显示；`level` 按字节判断（`used×100 ≥ limit×80` 为 warn，`≥ limit×95` 为 danger，否则 ok；79.96% 显示 80.0 仍是 ok）；**danger 只显示红色提醒、照样能传，不等于 507**；`photos_left = floor(max(0, limit−used)/512000)`；`store` 与 `/api/health` 的 `photo_store` 一致。
- 搬家：`node scripts/migrate-photos --from r2 --to kv`（先停 wrangler dev、先备份 `.wrangler/state`）。

## 8. 登录与权限
- 公开：`GET /api/health|categories|settings|me|dishes|dishes/:id`、`GET /api/photos/:key`。没登录时 `draft`、`requested_note` 为 null。
- 厨房写操作 `/api/kitchen/*`：必须登录，否则 401。
  - 线上：Cloudflare Access。配了 `ACCESS_TEAM_DOMAIN` + `ACCESS_AUD` 后，从 `Cf-Access-Jwt-Assertion` 头或 `CF_Authorization` cookie 取 JWT，用 `https://<team>/cdn-cgi/access/certs` 的公钥验 RS256，iss 必须与团队域名完全一致、aud 必须包含 ACCESS_AUD、未过期。
  - 本地：`DEV_AUTH=1` 时 `POST /api/dev/login` 种 `koala_dev_auth=1` cookie。**只要配了 ACCESS_TEAM_DOMAIN 或 ACCESS_AUD（`isLocalEnv()` 为 false），DEV_AUTH 自动失效。**
- 厨驼 `/api/chef/*`：请求头 `X-Chef-Key` 必须等于 `CHEF_KEY`（SHA-256 后常量时间比较）。密钥只在 `worker/.dev.vars`（600，不进 git）。

## 9. 环境变量
| 变量 | 默认 | 说明 |
|---|---|---|
| `PHOTO_STORE` | `kv` | 照片存哪：kv / d1 / r2 |
| `STORAGE_LIMIT_BYTES` | 996147200 | 只在本地生效：临时调低容量上限测 507。线上配了也不生效，固定 996147200 |
| `KV_DAILY_WRITE_LIMIT` | 1000 | KV 每天 put+delete 上限。本地可调成 5 测 429 |
| `CHEF_CLAIM_TTL_MIN` | 30 | 厨驼领取后独占多少分钟 |
| `CHEF_MOCK` | 0 | 1=自动出示例草稿（只用于联调） |
| `CHEF_KEY` | （.dev.vars） | 厨驼密钥 |
| `DEV_AUTH` | （.dev.vars 里为 1） | 本地模拟登录 |
| `ACCESS_TEAM_DOMAIN` / `ACCESS_AUD` | 空 | 线上 Access 配置；配了任意一个即视为线上（`isLocalEnv()` 为 false） |
| `STORAGE_USED_SIM` | 不配 | 只在本地生效：模拟“已用字节数”。线上配了也不生效 |

### 两个本地开关（测满额用）
是否本地由 `src/auth.ts` 的 `isLocalEnv()` 判断（`ACCESS_TEAM_DOMAIN`、`ACCESS_AUD` 都没配 = 本地），和 `DEV_AUTH` 用的是同一个函数。线上即使配了这两个变量也一律不读，容量上限固定 996,147,200。
- **`STORAGE_USED_SIM`**：把已用量直接当成这个数，用来测 507 和用量条，不用真的塞满照片。例：`npx wrangler dev --local --port 8801 --var STORAGE_USED_SIM:996147000`，再传任何一张照片就是 507。**线上一律忽略。** 测 danger：`--var STORAGE_USED_SIM:950000000`（95.4%，红色提醒但照样能传）。
- **`STORAGE_LIMIT_BYTES`**：临时把容量上限调小，例：`--var STORAGE_LIMIT_BYTES:300000`。线上配了也不生效。
- 测 429：`--var KV_DAILY_WRITE_LIMIT:5`（第 6 次写入起 429）。
- 这些只在启动命令或 `.dev.vars` 里改，改完重启 wrangler dev；别在 8787 上开（那里有大王的 7 道菜）。

## 10. 已知限制
- KV 最终一致：同一机房立即可见，其他机房最多约 60 秒才看到新照片或删除。
- KV 次数是 put+delete 合并计数（比官方 1,000 写 + 1,000 删更保守），按 UTC 零点（多伦多晚上 7 点 / 8 点）重置。
- Workers 免费版每次请求最多 50 次 D1 查询、CPU 10ms：KV 次数已改成批量计数；9 张大图一次上传在本地没问题，线上 CPU 余量需上线后观察。
- 本地 CORS 全开（方便前端 dev server 联调）；线上同源访问。
- `koala_dev_auth` cookie 只用于本地；线上靠 Access。
- 照片键列名叫 `r2_key` 是历史原因，三种存储都用它。
- 厨驼目前要手动跑 `chef.py`，还没有定时检查（线上版需大王审批）。
- `worker/test/`（后端工程师的接口测试）尚未提交到 round-1，从零按 README 跑时需等工程师提交。
