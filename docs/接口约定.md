日期：2026-11-09　状态：草案，前端有意见直接改本文件并告诉后端组长

## 目录分工
- `worker/`：后端（Cloudflare Worker + D1 + R2 + Workers AI），后端组负责
- `web/`：前端，前端组负责；构建产物放 `web/dist/`
- `docs/`：约定文档，两边都可改
- 本地联调：在 `worker/` 运行 `npx wrangler dev`，端口 8787。Worker 同时用 assets 托管 `../web/dist`，所以 `http://localhost:8787/` 是前端，`/api/*` 是接口，同源，无跨域。前端自己开 dev server 时把 `/api` 代理到 8787 即可（开发期后端也放开 CORS）。

## 通用约定
- 所有接口前缀 `/api`，JSON 用 UTF-8，字段名小写下划线。
- 成功：HTTP 200/201，直接返回数据对象。
- 失败：HTTP 4xx/5xx，返回 `{"error":{"code":"字符串","message":"给大王看的中文提示"}}`。前端直接显示 message。
- 常见 code：`VALIDATION`（400）、`NOT_FOUND`（404）、`TOO_LARGE`（413）、`BAD_TYPE`（415）、`AI_FAILED`（502）、`INTERNAL`（500）。
- 时间为 ISO 8601（UTC）。
- 登录：线上由 Cloudflare Access 挡在外面，接口本身不做登录；本地无登录。

## 分类（固定）
`GET /api/categories` → `{"categories":["家常菜","汤羹","主食","小吃点心","甜品饮品","其他"]}`

## 菜品对象 Dish
```json
{
  "id": "uuid",
  "name": "番茄炒蛋",
  "category": "家常菜",
  "note": "少放糖",              // 可为 null
  "photo_url": "/api/photos/<key>",
  "ingredients": [ {"name":"鸡蛋","amount":"3个"} ],
  "steps": [ {"text":"鸡蛋打入碗中，加 1 克盐，用筷子打散约 30 秒至起泡","heat":"","time":"30秒"} ],
  "tips": ["番茄选熟透的更出汁"],       // 可为空数组
  "servings": "2人份",                 // 可为 null
  "total_time": "15分钟",              // 可为 null
  "ai_status": "pending | done | failed",
  "ai_error": null,                    // failed 时为中文原因
  "created_at": "...", "updated_at": "..."
}
```
- steps 每项：`text` 必有（完整一句，包含用量/火候/时间）；`heat`（火候，如“中火”，可为空串）、`time`（如“2分钟”，可为空串）方便前端做漫画小标签。
- 列表接口返回精简版 DishSummary：`id,name,category,photo_url,ai_status,created_at`。

## 接口
| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/dishes?category=家常菜` | 列表，按 created_at 倒序；不传或 `全部` 返回全部。→ `{"dishes":[DishSummary]}` |
| POST | `/api/dishes` | 上传。`multipart/form-data`：`name`(必,≤30字) `category`(必) `photo`(必,jpg/png/webp,≤10MB) `note`(可,≤200字)。**同步生成**：返回时已生成完（ai_status=done），或生成失败（ai_status=failed，菜名照片已保存）。→ 201 `Dish`。前端在请求期间显示加载动画（目标 30 秒内）。 |
| GET | `/api/dishes/:id` | 详情 → `Dish` |
| PATCH | `/api/dishes/:id` | 编辑文字字段，JSON：可含 `name category note ingredients steps tips servings total_time`，只改传了的 → `Dish` |
| PUT | `/api/dishes/:id/photo` | 换照片，`multipart/form-data` 的 `photo`，旧图从 R2 删除 → `Dish` |
| POST | `/api/dishes/:id/regenerate` | 重新生成食材/步骤，覆盖旧的（确认弹窗由前端做）。可选 JSON `{"note":"这次加了土豆"}` 更新备注后再生成 → `Dish` |
| DELETE | `/api/dishes/:id` | 删除，同时删 R2 照片 → `{"ok":true}` |
| GET | `/api/photos/:key` | 读照片（Worker 从 R2 读，桶不公开），带 Content-Type 和缓存头 |
| GET | `/api/health` | `{"ok":true,"ai_mode":"mock|real"}` 前端可用来显示“模拟 AI”小标记 |

## AI 模式
- `AI_MODE=mock`（本地默认）：不联网，按菜名返回结构正确的示例菜谱，便于前端开发。
- `AI_MODE=real`：调用 Workers AI。

## v1.1 变更提议（前端组长，2026-11-09 22:40，依据 ../AI权衡结论.md：AI 可选）
AI 结果一律是**草稿**，大王确认后才落库；手写模式不碰 AI。
1. 新增 `POST /api/ai/generate`，JSON `{name, category, note?}` → `{ingredients, steps, tips, servings, total_time}`，**不落库**。上传页「AI 帮我写」和「重新生成」草稿都用它。
2. `POST /api/dishes`（multipart）改为**不再自动调 AI**：除 name/category/photo/note 外，可带 `ingredients` `steps` `tips`（JSON 字符串）、`servings` `total_time`、`source`（`ai|manual`）。手写模式允许食材/步骤都为空、只写 note。→ 201 Dish。
3. Dish 增加 `source`: `ai | manual`；`ai_status` 保留兼容（手写为 `"none"`）。
4. 已存菜品的 `POST /api/dishes/:id/regenerate` 保留（详情页「让 AI 重写」用，前端弹确认）。
5. 设置：`GET /api/settings` → `{"ai_enabled":true}`；`PATCH /api/settings` JSON `{"ai_enabled":false}`（存 D1 一张 settings 表或 KV 都行，选免费的）。关掉后前端隐藏所有 AI 入口，后端 AI 接口返回 403 `AI_DISABLED`。
6. 新错误码：`AI_QUOTA`（429，免费额度用完，message 如“今天 AI 厨师下班啦，先自己记一笔吧”）、`AI_DISABLED`（403）。`AI_FAILED`（502）不变。前端遇到这三种都友好提示并自动切到手写模式，已填内容不丢。
7. `/api/health` 增加 `ai_enabled`。mock 模式请支持用菜名含「失败」触发 AI_FAILED、含「额度」触发 AI_QUOTA，方便测试截图。
