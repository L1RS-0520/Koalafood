## P1
**P1-1　编辑页保存总带上全部内容字段，只改菜名/分类/备注也会作废厨驼任务，并把来源改成手写**
- 位置：`web/src/pages/EditPage.tsx:190`（`updateDish(dish.id, { name, category, note, ...c })`，`c = cleanContent(content)` 总是带齐 `ingredients/steps/tips/servings/total_time`）；提醒只在 `:203`、`:226-229` 对 pending/draft 显示。
- 问题：约定 §4.1 规定，PATCH 请求里**只要出现**任何一个内容键（值没变也算），就会变成 source=manual、chef_status=confirmed，并清掉 draft、requested_note 和厨驼任务。所以：
  ① pending 的菜只改个名，厨驼任务就没了；
  ② 已确认的厨驼菜谱只改备注，来源也会从「厨驼写的」变成手写，而且这种情况页面上没有任何提醒。
- 建议：保存前和 `dish` 原值比较，只把**真正改了的**字段放进 PATCH。内容五个字段都没改时，只发 `name/category/note`。照片操作已经走单独的接口，不受影响。

**P1-2　mock 的 PATCH 一律改成 confirmed + manual，和真实接口规则不一致**
- 位置：`web/src/api/mock.ts:248-253`（注释还写着「约定 v2.1」）。
- 问题：真实接口只有带了内容键时才改状态和来源（约定 §4.1，来自需求 §12）；只改 name/category/note 时，source 和 chef_status 都不变。mock 一律改，P1-1 在 mock 模式下就测不出来。
- 建议：mock 也按「patch 里有没有内容键」分开处理，注释改成 v2.3.2 §4.1。

## P2
- **P2-1**　`api/http.ts:27`：413 的兜底文案「照片太大啦，单张不能超过 1MB」和约定 §2 的格式不一样。只有后端返回体解析不了时才会用到，建议改成 `tooLargeText(null)`（「照片太大了，上限 1,024KB」）。
- **P2-2**　`api/normalize.ts:141,143,144,157`：还在兼容已经删掉的平铺字段 `used_bytes/limit_bytes/used_pct/ops_today/ops_limit`。后端已经不返回这些字段，建议删掉兼容分支，避免以后误用。
- **P2-3**　`api/contract.ts:2`：注释写「依据……v2.1 最终定稿（唯一准绳）」，已过时。建议改成「接口约定 v2.3.2 开头的当前有效版」。
- **P2-4**　`api/contract.ts:6-7,21-30`：`STATUS_FIELD_FALLBACKS`（recipe_status/status）和 `STATUS_ALIASES` 里的 waiting/drafted/failed/done/none 都是 v2 草案留下的。后端只会返回 pending/draft/confirmed，可以删掉；要保留的话，建议在注释里写明「只为兼容旧 mock 数据」。
- **P2-5**　`api/mock.ts:110,114`：mock 的 507/429 判断是「已用 ≥ 上限」「次数 ≥ 1000」，真实接口是「**已用 + 本次总字节 > 上限**」「已用次数 + **本次张数** > 上限」，而且两个都超时先判 507。临界值附近的行为会不一样，比如已用 = 上限 − 1KB 时传 500KB：真实接口返回 507，mock 放行。建议按真实规则算，传入本次的字节数和张数。
- **P2-6**　`api/mock.ts:95,104,120`：mock 的 403、413 文案和后端不同。后端是「厨驼已在设置里关闭，请先打开或改为自己写」和「照片太大了（1,030KB），上限 1,024KB」，mock 是「照片太大啦，单张不能超过 1MB」「第 1 张照片超过 1MB」。页面上 403 会直接 toast 出 message，所以 mock 和真实环境看到的字不一样。建议 mock 直接复制后端原文。
- **P2-7**　`api/types.ts:69`：`DishSummary.total_time` 标成可选，注释写「后端若在列表里带上」。v2.3.2 起后端一定返回这个字段（字符串或 null），建议改成必有的 `total_time: string | null`，注释写明「只有已确认的值」。
- **P2-8**　`api/types.ts:75-81` 的 `Health` 少了 `chef_mock`、`photo_store`、`orphan_photos`；`api/types.ts:125` 的 ApiError 注释少了 `STORAGE_QUOTA`、`STORAGE_FULL`。都不影响功能，补齐即可。
- **P2-9**　`components/StorageMeter.tsx:27,33,77`：「今天已传 x/1000 次」及 ≥80% 提醒对所有存储都显示。后端在 store 不是 kv 时也会返回 `daily_ops.limit=1000`，但并不按它拦截（约定 §3.5）。建议只在 `store === 'kv'` 时显示次数相关提示。另外 `api/normalize.ts:108` 的 `photo_count` 缺省值是 1，后端总会返回这个字段，影响不大。

## 没问题、不用改的
- 列表和详情请求都加了 `cache: 'no-store'`，轮询能拿到新状态（`api/http.ts:64,68,128`）。
- mock 遵守了隐私规则：未登录时不给 draft、requested_note、chef_message（`api/mock.ts:69-80`）。
- 详情页的 confirm 不带内容，按草稿原样确认；编辑页确认时把修改后的内容整份发出去，由后端严格校验（`pages/DishPage.tsx:242`，`pages/EditPage.tsx:187`），符合约定。
- 上传前按 1MB 压缩，HEIC 和超过 10MB 的原图在选图时就提示（`api/contract.ts:90-101,130-146`）。
