## 状态字段
Dish 和 DishSummary 都带 `recipe_status`：
| 值 | 含义 | 前端表现 |
|---|---|---|
| `waiting` | 待写：已交给厨驼，还没草稿 | 卡片/详情显示「厨驼正在写菜谱」+小羊驼厨师动画，前端每 10 秒轮询 |
| `drafted` | 已出草稿：厨驼交稿，大王未确认 | 卡片角标「草稿待确认」，详情页显示可编辑草稿 +「确认保存」「再找厨驼改」「不要了」 |
| `confirmed` | 已确认：正式菜谱（手写保存或确认草稿后） | 正常漫画分格详情 |
| `failed` | 厨驼说写不了（照片看不清等），带 `chef_message` | 友好提示 +「再找厨驼」「自己写」 |
另：`source`: `chef | manual`（最终内容来源）；`draft`：仅 drafted 时非空，结构 `{ingredients, steps, tips, servings, total_time, chef_message?}`；正式内容仍在顶层 `ingredients/steps/tips/servings/total_time`。`requested_note`：大王给厨驼的要求（可空）。

## 大王用（前端调用）
| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/dishes` | multipart：name category photo note? + `mode`=`chef|manual`。manual 可带 ingredients/steps/tips（JSON 字符串，可全空）→ confirmed；chef → waiting。chef 开关关闭时传 chef 返回 403 `CHEF_DISABLED`。→ 201 Dish |
| POST | `/api/dishes/:id/ask-chef` | JSON `{note?}`，(重新)交给厨驼 → waiting；已有正式内容保留不动，直到新草稿被确认 |
| POST | `/api/dishes/:id/confirm` | JSON 可带大王改过的 `ingredients steps tips servings total_time`（不带就用草稿原样）→ 写入正式内容，status=confirmed，清空 draft，source=chef |
| POST | `/api/dishes/:id/discard-draft` | 丢弃草稿；有正式内容回 confirmed，没有则 confirmed+空内容（详情页显示“还没写步骤”）|
| PATCH | `/api/dishes/:id` | 手动编辑正式内容（同 v1），source 改 manual |
| GET | `/api/settings` / PATCH | `{"chef_enabled":true}`；关掉后前端隐藏所有「找厨驼」入口 |
| GET | `/api/health` | `{"ok":true,"chef_enabled":true,"waiting_count":2}` |
列表 `GET /api/dishes` 的 DishSummary 加 `recipe_status`、`source`。

## 厨驼用（后端+厨驼对接，前端不调）
- `GET /api/chef/queue` → waiting 的菜（含 photo_url、name、category、note、requested_note）
- `PUT /api/chef/dishes/:id/draft` JSON 草稿 → drafted；或 `{"failed":true,"chef_message":"..."}` → failed
- 鉴权：请求头 `X-Chef-Key`，本地用 `.dev.vars` 里的 CHEF_KEY（不进 git）；线上密钥属上线审批事项。
- 今晚本地 demo：厨驼在共享电脑上用脚本领取 waiting 菜并提交草稿；mock 模式另提供 `CHEF_MOCK=1`：waiting 满 20 秒自动出示例草稿，菜名含「失败」则出 failed，方便前端联调截图。
