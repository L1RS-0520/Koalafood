# 厨驼使用说明（考拉食堂 · 本地联调版）

日期：2026-11-09　作者：羊驼后端组长　适用：接口约定 v2.3

厨驼的活：领取大王标成「找厨驼写」的菜 → 看照片和备注 → 写食材和步骤草稿 → 交稿。交稿后菜变成 `draft`（待大王确认），大王确认后才成为正式菜谱。

## 0. 先确认后端在跑

```bash
curl -s http://localhost:8787/api/health
# 正常：{"ok":true,"chef_enabled":true,"chef_pending":7,...}
```
连不上就启动（在共享电脑上）：
```bash
cd /workspace/kokotech/projects/koala-canteen/app/worker
nohup npx wrangler dev --local --port 8787 --ip 0.0.0.0 > /tmp/koala-worker.log 2>&1 &
```

## 1. 密钥（不用手动处理）

- 密钥位置：`app/worker/.dev.vars`，变量名 `CHEF_KEY`。
- `tools/chef.py` **会自动读取**它，**不要手动复制、不要贴到聊天或任何文件里**。脚本从不打印密钥。
- 也可以用环境变量 `CHEF_KEY` 覆盖（一般不需要）。
- 如果提示“找不到厨驼密钥”：在 `app/worker` 下运行 `./scripts/init-dev-vars`，再重启 wrangler dev。

## 2. 脚本用法

都在 `app/` 目录下运行（`cd /workspace/kokotech/projects/koala-canteen/app`）：

| 命令 | 作用 |
|---|---|
| `python3 tools/chef.py list` | 列出待写的菜（pending），含 id、菜名、分类、照片张数、备注 |
| `python3 tools/chef.py show <id>` | **领取**这道菜，把全部照片下载到 `/tmp/koala-chef/<id>/1.jpg、2.jpg…`（第 1 张是封面），并显示菜名、分类、备注、大王的要求、照片路径 |
| `python3 tools/chef.py show <id> --no-claim` | 只看不领 |
| `python3 tools/chef.py template` | 输出草稿 JSON 模板 |
| `python3 tools/chef.py submit <id> <草稿.json>` | 交稿；`<草稿.json>` 写 `-` 表示从标准输入读 |

通用选项：`--json`（输出 JSON，方便程序处理）、`--base http://localhost:8787`（默认就是这个，也可设环境变量 `KOALA_API`）。

### 示例

```bash
python3 tools/chef.py list
# 待写菜品 7 道：
# - f99bb52e-…  番茄炒蛋  [家常菜]  照片 3 张
#     备注：少放糖

python3 tools/chef.py show f99bb52e-c727-44b5-954d-17a26b04818f
# 菜名：番茄炒蛋 / 分类：家常菜 / 备注：少放糖
# 照片 3 张（第 1 张是封面）：
#   /tmp/koala-chef/f99bb52e-…/1.jpg …

python3 tools/chef.py template > /tmp/番茄炒蛋.json   # 改写成真正的菜谱
python3 tools/chef.py submit f99bb52e-c727-44b5-954d-17a26b04818f /tmp/番茄炒蛋.json
# 交稿成功：番茄炒蛋（…）现在是 draft 状态，等大王确认。
```

- 领取后 30 分钟内别人不能再领（重复领会提示 409，如果是你自己刚领的，`show` 会提醒后照样下载照片）。
- 只有 pending 的菜能交稿；交过一次就变 draft，再交会报 409 `BAD_STATE`。大王点了「让厨驼重写」才会重新变回 pending。
- 校验失败时脚本会把后端的中文原因逐条打印出来（退出码 2），改完再交即可。

## 3. 草稿 JSON 格式

```json
{
  "ingredients": [ {"name": "鸡蛋", "amount": "3个"} ],
  "steps": [
    {"text": "热锅倒 15 毫升油，烧到微微冒烟，倒入蛋液大火炒 1 分钟至八成熟盛出", "heat": "大火", "time": "1分钟", "caption": "嫩嫩的！"}
  ],
  "tips": ["番茄选熟透的更出汁"],
  "servings": "2人份",
  "total_time": "15分钟",
  "chef_message": null
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `ingredients` | 是 | 食材数组，至少 1 项，最多 40 项。`name` 必填（≤20 字），`amount` 用量（≤20 字，如“300克”“2汤匙（30毫升）”“适量”尽量少用） |
| `steps` | 是 | **3–12 步**，按顺序。`text` 必填（完整一句，≤300 字）；`heat` 火候（大火/中大火/中火/中小火/小火/微火/关火，或空串）；`time` 时间（如“2分钟”“30秒”，≤12 字）；`caption` 漫画格对白（**≤12 字，超长会被截断**） |
| `tips` | 否 | 小贴士字符串数组，最多 10 条 |
| `servings` | 否 | 份量，如“2人份” |
| `total_time` | 否 | 总时长，如“25分钟” |
| `chef_message` | 否 | 写不了时给大王的话。**只有带了它，食材和步骤才允许都是空数组**：`{"chef_message":"照片看不清是什么菜，大王能补一句备注吗？","ingredients":[],"steps":[]}` |

后端会自动：去掉步骤开头的“1.”“第一步：”编号、把“旺火/猛火”统一成“大火”、“文火”统一成“小火”、截断超长的 caption/time，并在交稿结果里以“提醒”列出。

## 4. 写作质量要求（大王会照着做菜）

1. **每一步都写清楚**：
   - 用量：具体到克、毫升、汤匙/茶匙（括号注毫升更好），不写“少许”“适量”（盐、胡椒实在要写也给个参考量，如“约 2 克”）。
   - 火候：大火 / 中火 / 小火，同时填进 `heat`。
   - 时间：分钟或秒，同时填进 `time`。
   - 判断标准：如“炒至表面微焦”“煮到筷子能轻松戳透”“油面出现细纹”。
2. **先看照片和备注再写**：照片能看出的做法（汤色、是否勾芡、配菜、切法）要和菜谱一致；备注是大王的实际做法或要求（如“少放糖”“加了土豆”），必须体现在食材和步骤里；有“大王的要求”的按要求重写。
3. 步骤 3–12 步、全中文、按实际操作顺序；备料可以合成一步。
4. `caption` 写成俏皮的漫画对白，≤12 字，如“下锅！”“滋滋冒油～”“出汁啦！”“合体！”，每步尽量不重复。
5. `tips` 写真正有用的诀窍（防粘锅、挑食材、保存方法），1–3 条即可。
6. 实在判断不出是什么菜或做法，用 `chef_message` 说明，不要硬编。

## 5. 常见报错

| 提示 | 原因 / 处理 |
|---|---|
| 连不上 http://localhost:8787 | wrangler dev 没在跑，见第 0 节 |
| 401 厨驼密钥不对 / 找不到厨驼密钥 | `.dev.vars` 被重新生成过但 wrangler dev 没重启；重启即可 |
| 409 CONFLICT | 30 分钟内已被领取 |
| 409 BAD_STATE | 这道菜不是 pending（已交过稿或大王已处理） |
| 400 VALIDATION | 草稿格式不对，按打印出来的原因改 |
| 404 NOT_FOUND | id 不对或菜已被删除 |
